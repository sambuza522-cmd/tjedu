# harness-install

`<루트>` = 하네스 저장소 루트 절대경로(이 사본: `D:/manhattan/fat-man/_apps/tjedu` · 원본: harness `D:/manhattan/fat-man/harness`).
`<대상>` = 하네스를 깔 프로젝트 루트 절대경로. 명령·프롬프트에 적을 때 절대경로로 치환한다. 상대경로는 러너가 받지 않는다.

설계 근거는 `<루트>/_workspace/harness-install-2026-09-25/spec-install.md` 다 — 후보안과 판정 공란은 그 파일이 들고 있다.
러너가 그 후보 중 무엇을 골랐는지는 `<루트>/tools/harness-install.py` 머리말의 「이 구현이 고른 값」 절에 후보 번호까지 적혀 있다. 이 절차는 그 둘을 다시 쓰지 않고, 언제 부르고 결과를 어떻게 읽는지만 적는다.

## 1. 언제 부르는가

- 프로젝트 자리에 `.claude/` 가 아직 없고 거기서도 절차·게이트를 쓰려 할 때.
- 원본(하네스)의 절차·워크플로가 바뀌어 이미 깔린 자리에 반영하려 할 때 — 다만 그 자리에 `.claude/harness-sync.py` 가 이미 있으면 그 도구가 더 좁은 일을 한다(아래 6절).
- 부르지 않는 경우는 description 의 부정조항 그대로다.

## 2. 부르기 전에 확인할 것

1. `<대상>` 이 실재하는 폴더인가 — `ls <대상>`.
2. `<대상>` 아래 검문할 문서가 있는가 — 없으면 러너가 exit 4 로 멈춘다(3절). 미리 보려면 `ls <대상>/docs`.
3. `<대상>` 이 git 저장소인가 — 아니면 이 설치를 git 으로 되돌릴 수단이 없다. 러너가 첫머리에 그 사실을 찍는다.
4. `<대상>` 이 `D:/manhattan/fat-man` 아래인가 — 아니면 `--allow-outside` 가 필요하다. 하네스 저장소 자신과 사용자 홈 `.claude` 아래는 그 플래그로도 열리지 않게 짜여 있다(코드 분기 `main()` 의 exit 6 세 갈래).

## 3. 러너 실행 — 미리보기 먼저

```
python <루트>/tools/harness-install.py --target <대상> --dry-run
python <루트>/tools/harness-install.py --target <대상>
```

- `--target` 에 기본값이 없다. 빠뜨리면 exit 2 다.
- `--dry-run` 은 무엇을 깔지만 찍는다 — 파일을 만들지 않는다.
- `--guarded "<글롭>,<글롭>"` 로 검문 범위를 바꾼다. 기본은 `docs/**` 두 줄이다.
- `--max-guarded N` 으로 매치 상한을 준다. 기본은 상한 없음이다 — 수치는 이 절차가 정하지 않는다.
- `--workflows a.js,b.js` 를 주면 워크플로를 사람이 고른 목록으로 깐다. 안 주면 러너가 파일 본문을 훑어 대상 트리 밖 절대경로 상수를 든 것을 빼고, 뺀 이유를 파일:행으로 찍는다.
- `--force` 는 이미 있는 파일 중 내용이 다른 것을 `.bak-<스탬프>` 를 만든 뒤 덮는다.

종료코드 — 이 값으로 다음 수가 갈린다.

| 코드 | 뜻 | 다음 수 |
|---|---|---|
| 0 | 설치 완료, 또는 `--dry-run` 계획 출력 | 4절로 간다 |
| 2 | 입력·정본 문제 — `--target` 없음·상대경로·대상 폴더 없음·하네스 스킬 원본 부재 | 인자를 고쳐 다시 부른다. 원본 부재면 `<루트>/.claude/skills` 를 먼저 본다 |
| 3 | 재설치인데 내용이 다른 파일이 있다. 아무것도 덮지 않고 멈췄다 | 5절 |
| 4 | 검문 글롭이 대상 실재 파일을 0건 덮는다(또는 상한 초과). 아무것도 만들지 않았다 | 6절 |
| 5 | 쓴 뒤 확인 실패 — 파일이 없거나 JSON 문법이 깨졌다 | 대상 `.claude` 를 사람이 보고 hq-builder 로 회송 |
| 6 | 대상 자리 거부 — 허용 루트 밖, 또는 하네스 자신·사용자 홈 `.claude` 아래 | 대상을 바꾸거나 `--allow-outside`. 뒤 두 자리는 이 절차로 열지 않는다 |

## 4. 결과 읽기 — exit 0

러너 출력에서 이 넷을 그대로 옮겨 적는다. 러너가 안 찍은 것을 지어내지 않는다.

- 검문 매치 수와 첫 세그먼트별 내역 — 이 수가 「빈 껍데기 아님」의 근거다. `refs/`·`out/` 같은 외부 세그먼트가 큰 수로 섞여 있으면 `--guarded` 를 좁혀 다시 깐다.
- 파일별 상태 — `신규` / `동일` / `다름`, 그리고 쓰기·건너뜀·백업 건수.
- 안 깐 워크플로와 그 이유 줄.
- 마지막 파워셸 줄 — 차단 스위치를 켜는 명령이다. 러너도 이 절차도 그 파일을 만들지 않는다(7절).

이 설치만으로 카나리아(deny 7건이 실제로 거부를 내는지)가 확인된 것은 아니다. 러너도 그 문장을 출력 끝에 찍는다 — 보고에 그대로 남긴다.

## 5. exit 3 — 재설치에서 갈라졌을 때

러너는 덮지 않고 멈춘다. 순서는 이렇다.

1. 무엇이 다른지 본다 — `python <대상>/.claude/harness-sync.py --check`.
2. 대상 쪽 수정이 남길 가치가 있으면 그 파일을 사람이 따로 뺀 뒤 `--force` 로 다시 깐다. `--force` 는 덮기 전에 `.bak-<스탬프>` 를 남긴다.
3. 원본 쪽이 낡았으면 `<루트>` 원본을 먼저 고친다 — 고치는 것은 hq-builder(코드)·hq-scribe(문서) 몫이고 이 절차가 하지 않는다.

## 6. exit 4 — 검문 매치 0건

대상에 검문할 문서가 없다는 뜻이다. 이 상태에서 설치를 강행하면 선언만 있고 지킬 것이 없는 껍데기가 된다 — 러너가 그래서 멈춘다.

- 대상에 문서가 정말 없으면 문서가 생긴 뒤에 다시 부른다.
- 문서 자리가 `docs/` 가 아니면 `--guarded` 로 그 자리를 준다. 준 글롭이 몇 건을 덮는지는 러너가 찍는다.
- 상한 초과로 멈춘 것이면 `--guarded` 를 좁히거나 `--max-guarded` 값을 사람이 다시 정한다.

## 7. 이 절차가 하지 않는 것

- 차단 스위치 `<대상>/.claude/hq-gate-deny.on` 만들기. 러너는 켜는 줄을 찍기만 한다. 켜는 것은 사용자다.
- 전역 홈(`~/.claude`) 아래 배치 — 사용자 리뷰 뒤에 사용자가 한다.
- 레일 4종 수정 — `transfer-gate.py` · 전역 `hq-gate.json` · `install-global.py` · `agent-registry.json`.
- `hooks.PreToolUse` 등록. 이번 러너는 `permissions.deny` 7건만 쓴다. `Bash`·`PowerShell` 로 같은 파일을 쓰는 경로와 `Write`(새로 만들기)는 그 7건에 걸리지 않는다 — 대상 `README.md` 3절에 같은 내용이 적힌다.
- 깔고 난 뒤의 항목별 등급 판정 — `harness-checklist` 로 보낸다.

## 8. 회송

| 상황 | 어디로 |
|---|---|
| exit 5, 또는 러너 자체를 고쳐야 함 | hq-builder |
| 깔린 뒤 문서·README 문구 정정 | hq-scribe |
| `--max-guarded` 같은 수치 임계치 확정 | 지휘부·사용자 |
| 카나리아 실행(거부가 실제로 나는지) | 사용자 세션 — 이 절차는 그 결과를 관측했다고 적지 않는다 |
| 전역 배치·차단 스위치 켜기 | 사용자 |
