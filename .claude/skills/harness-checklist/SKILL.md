# harness-checklist

`<루트>` = 프로젝트 루트 절대경로(이 사본: `D:/manhattan/fat-man/_apps/tjedu` · 원본: harness `D:/manhattan/fat-man/harness`). 명령·프롬프트에 적을 때 절대경로로 치환한다. 상대경로 금지.

정본은 `<루트>/docs/harness-checklist.md` 다 — 9항목의 정의·통과 기준·사고 근거는 그 파일이 정한다. 이 스킬은 그 문서를 다시 쓰지 않고, 러너를 어떤 순서로 돌리고 미통과를 어디로 보내는지만 적는다. 항목 자체를 고치려면 이 스킬이 아니라 정본 문서를 고친다.

## 1. 언제 부르는가

- 하네스 자산을 새로 만들거나 고친 직후 — `.claude/agents/*.md` · `.claude/skills/*/SKILL.md` · `tools/*.py` · 게이트·훅.
- 남의 하네스를 인수하거나 소급 점검할 때 — `--target` 으로 그 루트를 지목한다.
- 부르지 않는 경우는 description 의 부정조항 그대로다. 특히 **수리 중간에는 부르지 않는다** — 고치고 나서 한 번, 회송 결과가 돌아온 뒤 한 번이다.

## 2. 러너 실행

```
python <루트>/tools/harness-checklist.py --target <검사할 하네스 루트 절대경로>
```

- `--target` 기본값은 저장소 자신이다. 다른 하네스를 볼 때만 적는다.
- `--only C5,C6` 로 항목을 좁힌다. `--no-run` 은 외부 명령을 돌리지 않는다(C2·C4·C6·C8·C9 가 자동판정불가로 보류된다).
- 러너는 **읽기 전용**이다. 파일을 만들거나 고치거나 지우지 않고, 로그도 남기지 않는다. 출력은 표준출력뿐이라 `--json` 같은 파일 산출 옵션이 없다.

종료코드 — 이 값으로 다음 수가 갈린다.

| 코드 | 뜻 | 다음 수 |
|---|---|---|
| 0 | 자동판정 전부 통과, 자동판정불가 0건 | 닫는다 |
| 2 | 인자·환경 오류 | 경로·`--only` 이름·매니페스트 JSON 을 고쳐 다시 돌린다 |
| 3 | 대상 0건 | 경로·매니페스트를 확인한다. 통과가 아니다 |
| 4 | 미통과 1건 이상 | 3절 |
| 5 | 미통과 0건, 자동판정불가 1건 이상 | 4절 |

## 3. 미통과(exit 4)가 나왔을 때 — 러너는 고치지 않는다

1. 러너 출력의 「미통과」 줄에 적힌 항목 기호를 그대로 옮긴다. 항목마다 사고 근거는 정본 문서의 「빠뜨려서 난 사고」 열에 있다.
2. 관할대로 회송한다 — 코드(`tools/**`·`.py`·매니페스트/설정 `.json`)는 hq-builder, 문서(`.md`)는 hq-scribe. 이 스킬 안에서 고치지 않는다.
   - 단 레일 4종(`transfer-gate.py`·`hq-gate.json`·`install-global.py`·`agent-registry.json`)과 `settings*.json` 은 수정 자체가 금지된 대상이라 hq-builder 관할 밖이다 — 회송하지 말고 사용자에게 올린다(`<루트>/.claude/skills/workflow-launch/SKILL.md:89` RULES 블록).
   - 러너 매니페스트 `<target>/.claude/harness-checklist.json` 은 레일 4종에 없다 — hq-builder 관할 그대로다.
3. 회송 결과가 돌아오면 같은 명령을 그대로 다시 돌린다. 「고쳤다」는 보고가 아니라 러너 출력이 닫는 근거다.
4. 회송 뒤 다시 돌린 것이 **재실행 1회**다. 재실행은 2회까지 하고, 2회째에도 같은 항목이 미통과면 사용자에게 올린다 — 재실행 3회째는 하지 않는다. (workflow-retry 의 재발사 상한과 같은 자리다 — `<루트>/.claude/skills/workflow-retry/SKILL.md:44` 「재발사 횟수 ≤ 2. 3회째는 발사 대신 사용자 보고」)

## 4. 자동판정불가(exit 5)를 통과로 올리지 않는다

자동판정불가는 통과가 아니다. 러너가 그 항목을 따로 세고 전용 종료코드로 내는 이유가 이것이다. 둘 중 하나로만 닫힌다.

- **선언으로 닫는 경우** — 매니페스트 `<target>/.claude/harness-checklist.json` 에 그 절을 적는다. 절마다 `"applies": false` 면 「개념없음」이고, 값을 적으면 자동판정 대상이 된다. 스키마와 예시는 러너 파일 헤더의 「매니페스트」 절에 있다(정본은 코드).
- **사람이 보는 경우** — C7' 은 과정성이라 선언으로도 자동화되지 않는다. 「옮기기 전에 참조 검사를 했는가」는 사후에 재구성되지 않으므로, 옮기기 **전에** 사람이 러너가 찍어 준 `grep -rlF` 명령을 돌리고 0건을 확인한다. C8 은 미커밋 변경과 `.bak` 이 둘 다 있을 때 어느 수정에 어느 백업이 붙는지 사람이 대조한다.

되돌리지 말 것 — 정본의 「반증으로 한 번 깨진 자리」 2건이다. C5' 를 「Write·Edit 부재」로만 쓰면 경계가 서지 않는다(Bash 를 가진 읽기 전용 노선이 `hq-auditor`·`hq-scout`·`security-auditor`·`static-analyzer` 4건 실재하며, 러너는 이 4건만 화이트리스트 예외로 둔다 — 이 명단은 러너 코드의 `DEFAULT_BASH_EXEMPT` 상수 고정이라 매니페스트로 늘릴 수 없다. 검사 대상이 `c5.bash_exempt` 를 적으면 러너가 인자·환경 오류(exit 2)로 거부한다. 늘려야 할 정당한 노선이 생기면 코드 상수 쪽을 hq-builder 로 회송한다). C7' 의 grep 에서 `--exclude-dir=.next` 를 빼지 않는다.

## 6. 완료 기준

- 러너 명령과 종료코드를 응답에 그대로 적었다. 「돌렸다」만 적지 않는다.
- 통과·미통과·개념없음·자동판정불가 4수를 러너 출력의 합계 줄에서 옮겼다. 머리로 세지 않는다.
- 미통과 0건이고, 자동판정불가는 0건이거나 항목별로 누가 무엇을 확인할지 적혔다.
- 수리는 이 스킬 밖(hq-builder·hq-scribe)에서 일어났고, 닫은 근거는 재실행 출력이다.
